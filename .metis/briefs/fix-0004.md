# fix-0004 — Daemon cannot start in the musl release build: the socket pin loses O_PATH

- **Type:** fix | **Risk:** high | **Priority:** p0
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-25
- **Plan:** .metis/plans/phase-0-plan.md §0.4

## Goal

`ship daemon` from the static musl release binary binds its unix socket and
serves `/healthz` (§0.4: "bind a unix socket at mode 0660 … refuse to start
if either cannot be bound as specified"), with every property fix-0002
established for the socket pin, and CI fails before release if the musl
build regresses.

## Architectural context

- `crates/ship-net/src/listener.rs` `identify()` opens the socket pin with
  `fs::OpenOptions::new().read(true).custom_flags(libc::O_PATH | libc::O_NOFOLLOW)`.
  std's unix `File::open` builds the flags as
  `O_CLOEXEC | access_mode | creation_mode | (custom_flags & !O_ACCMODE)`.
  Cause, checked against the definitions rather than assumed:
  - glibc: `O_ACCMODE = 0o3`, `O_PATH = 0o10000000`; the mask keeps O_PATH.
  - musl: `O_ACCMODE = (03 | O_SEARCH)` and `O_SEARCH = O_PATH`, so
    `O_ACCMODE = 0o10000003` and the mask clears O_PATH. The call becomes
    `open(path, O_RDONLY|O_NOFOLLOW|O_CLOEXEC)`; `open(2)` on a socket
    without O_PATH is `ENXIO` (os error 6). This matches the gate's strace
    exactly (`O_RDONLY|O_LARGEFILE|O_NOFOLLOW|O_CLOEXEC = -1 ENXIO`).
- Fix: open the pin with `libc::open(path, O_PATH | O_NOFOLLOW | O_CLOEXEC)`
  directly, wrap the fd in `OwnedFd`, convert to `fs::File` (so `fstat`
  via `File::metadata` and Drop are unchanged). No access mode is passed
  (O_PATH ignores it). The path is converted to a `CString`; an interior NUL
  is `InvalidInput`. Every fix-0002 property stays: the pin is taken while
  the bound socket is alive, checked to be a socket whose `(dev, ino)` equals
  `lstat(path)`, failure removes the new socket and returns `BindError::Io`
  with step `pin`, `is_ours()` and the umask behaviour are untouched.
- Search of the workspace for the same class of bug: the only
  `custom_flags` call is `listener.rs:196`. `crates/ship/src/config.rs` and
  `crates/ship/src/service.rs` use `OpenOptionsExt::mode()` only (a creation
  mode, not masked). The other `libc::` uses (`kill`, signals, errno,
  `getgrgid_r`, `geteuid`, `statvfs`, `fcntl(F_SETFD)`, `fchmod`, `socket`,
  `bind`, `listen`) pass no open flags. No `nix`/`rustix` call in the
  workspace's own code.
- The gap: `ci.yml` builds and tests gnu only, while `release.yml` ships
  `x86_64-unknown-linux-musl` / `aarch64-unknown-linux-musl`. The release's
  `no-network-smoke.sh` starts the daemon but only waits for the socket file
  to appear, which a daemon that binds, fails the pin and removes the socket
  can still satisfy for an instant; it does not require `/healthz` to answer.

## Definition of Done

1. `identify()` opens the pin through `libc::open` with
   `O_PATH | O_NOFOLLOW | O_CLOEXEC`, not through `OpenOptions::custom_flags`.
   No other change to `SocketFile`'s behaviour or public API.
2. A Linux test asserts the pin fd's `F_GETFL` includes `O_PATH` and its
   `F_GETFD` includes `FD_CLOEXEC`, so the musl CI job fails if the flag is
   lost again.
3. `ci.yml` gains a job that installs `musl-tools`, adds the
   `x86_64-unknown-linux-musl` target, sets
   `CC_x86_64_unknown_linux_musl=musl-gcc` (as `release.yml` does) and runs
   `cargo test --workspace --locked --target x86_64-unknown-linux-musl`.
4. `scripts/daemon-smoke.sh PATH/TO/ship` starts `ship daemon` on a temp
   state dir, socket and port, requires `GET /healthz` over the unix socket
   (`curl --unix-socket`) to return 200 within a timeout while the daemon
   process is still alive, then SIGTERMs it and requires the socket removed.
   It prints the daemon's log on failure.
5. `release.yml` runs `scripts/daemon-smoke.sh "$BIN"` on each Linux arch
   before the Package step, so a failure stops the archive being built.
6. `metis verify --post --slice fix-0004` is green. No new dependency.

## Test plan

- New `pin_is_o_path_and_cloexec` (Linux, listener.rs): bind, read the
  pin's `F_GETFL`/`F_GETFD`, assert `O_PATH` and `FD_CLOEXEC`.
- Existing listener tests unchanged, including fix-0002's
  `remove_leaves_a_successor_with_the_same_inode_number` and
  `pin_does_not_keep_the_socket_listening`; under the musl CI job they now
  exercise the musl path (all of them failed there before, at `bind_unix`).
- `scripts/daemon-smoke.sh`: run on release per Linux arch against the
  musl binary; `bash -n` and shellcheck-clean.
- Linux/musl runs cannot happen in this macOS session. Per the slice notes
  the supervisor builds the musl binary on a Linux host and runs the daemon
  and listener tests there; CI runs on push.
