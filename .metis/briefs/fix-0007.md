# fix-0007 — A flaky verification test, and no restart hint after an in-place upgrade

- **Type:** fix | **Risk:** low | **Priority:** p0
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-28
- **Plan:** .metis/plans/phase-1-plan.md Workstream 1.14: Recovery and invariants

## Goal

Make `only_an_answering_address_answers` (f-052, f-054) and the fake-docker
preflight tests deterministic without weakening what they prove, and tell the
operator to `sudo systemctl restart ship` when an in-place upgrade leaves a
daemon running another version (f-018).

## Architectural context

- `ship_daemon::push::answers(address)`: TCP probe used before an address is
  printed (OVERVIEW §3.3: the CLI never prints an address that does not exist).
- `ship_docker::preflight` over a fake `docker` shell script written once per
  test binary (`OnceLock`).
- `crates/ship/src/service.rs`: `install` talks to the host only through the
  `Host` trait (structured argv; a fake host in the unit tests).
- `HostInfo.version` (`/api/v1/host`) and the `ship-version` response header
  carry the daemon's `CARGO_PKG_VERSION`; the client's is the same constant.
- `ship host -o json` is a contract shape (ADR-0004); the text form is not.
- `scripts/install.sh` runs as the invoking user; `SHIP_CONFIG` names the
  client config, and a missing file means the local default socket.

Causes:

1. `only_an_answering_address_answers` drops its listener and then asserts
   the freed port does not answer. Any other process or test may bind the
   freed ephemeral port in between, so it answers. Fix: hold the port in a
   socket that is bound but not listening (no `SO_REUSEADDR`), so no one else
   can take it; assert it does not answer; then `listen()` on the same socket
   and assert `127.0.0.1:P` and `0.0.0.0:P` answer.
2. `failing_engine_is_unreachable` (fake_docker.rs:130, once in CI
   2026-11-27): not the same cause (no ports). Inferred cause, no CI log kept:
   ETXTBSY. The test process writes the fake script with an fd open for
   writing; a concurrent test in the same binary (`missing_cli_is_unreachable`,
   `missing_socket_is_unreachable`, which do not wait on the `OnceLock`) forks
   to spawn a child, the child inherits the write fd until its exec, and
   executing the script in that window fails "Text file busy". The probe then
   reads `Failed("Text file busy")`: status still `unreachable`, but the
   message lacks "Cannot connect" — the assertion that failed. Fix: the test
   process never opens the executed file for writing: write the script to a
   source file, and have a `cp` child create the executed copy. Same pattern
   in `fake_compose.rs` (same crate), fixed the same way.

## Definition of Done

1. `only_an_answering_address_answers` holds the port for its whole run and
   still proves: a bound, non-answering port is not answering; the same port
   answers on `127.0.0.1` and `0.0.0.0` once listening; a non-address does not.
2. The fake-docker and fake-compose scripts are never write-opened by the test
   process that executes them.
3. `ship service install`, when `systemctl is-active ship.service` succeeds:
   - daemon reports a version different from this binary → prints both
     versions and `sudo systemctl restart ship`;
   - daemon's version cannot be read → says so and prints
     `sudo systemctl restart ship`;
   - same version and unit changed → `sudo systemctl restart ship` (as before);
   - same version, unit unchanged → says it runs this version; no start hint.
   When it is not active: `Start the daemon:  sudo systemctl start ship`.
   The version check runs after every change and changes nothing itself.
4. `install.sh`, on Linux with a system-path prefix and an active
   `ship.service`, asks the local daemon (forced via `SHIP_CONFIG`) for its
   version through the installed binary and, if it differs or cannot be read,
   prints `sudo systemctl restart ship`.
5. `ship host` text shows the client version next to the daemon's when they
   differ. `-o json` shape unchanged.
6. `metis verify --post` green; f-052, f-054, f-018 resolved with evidence.

  unreadable version, and running this version with a changed unit; assert
  the printed next steps for each; existing mutating-call tests still exclude
  read-only `systemctl is-active`.

  versions; JSON unchanged.
- install-selftest.sh (Linux): a stub `systemctl` and a fake binary that
  answers `--version` and `host -o json`; a world-traversable prefix outside
  home; cases: active daemon on another version → restart hint; same version
  → no hint; daemon not active → no hint; the fake asserts `SHIP_CONFIG` is set.
- service-smoke.sh: second install with the daemon running prints that it
  runs this version and no restart hint.
