# fix-0005 — ship open fails over an ssh server that refuses unix-socket forwarding (Tailscale SSH)

- **Type:** fix | **Risk:** high | **Priority:** p1
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-25
- **Plan:** .metis/plans/phase-0-plan.md §0.7

## Goal

`ship open` against an ssh target shows the UI on a 127.0.0.1 port and
closes it when interrupted (§0.7) on any ssh server that can run
`ship dial-stdio`, including Tailscale SSH, which refuses streamlocal
(`-L port:/socket`) forwarding.

## Architectural context

- Today `crates/ship/src/open.rs` `over_ssh()` runs
  `ssh -N -T -o BatchMode=yes -o ExitOnForwardFailure=yes … -L 127.0.0.1:P:SOCKET -- HOST`
  (`SshTarget::forward_args`, `crates/ship-net/src/target.rs`). Tailscale
  SSH opens the listener and then refuses every channel ("socket path … is
  not in an allowed directory"), and `ship open` reports only a timeout.
- Every other command reaches the daemon with
  `ssh … -- HOST ship dial-stdio [--socket S]` (`SshTarget::ssh_args`,
  `ship_net::client::get`), which works over Tailscale SSH.
- Fix: one path, no OpenSSH `-L`. A new `ship_net::forward` module serves a
  127.0.0.1 listener (bound through the existing `bind_loopback`, which
  accepts no address) and carries each accepted TCP connection over its own
  `ssh … HOST ship dial-stdio` child, spawned with `SshTarget::ssh_args`
  (structured argv, `--` before HOST, values already validated by
  `Target::parse`). Concurrent children are bounded by a semaphore; a
  connection waits in the kernel backlog until a slot frees. On shutdown the
  listener is dropped first, then every child is killed and reaped before
  `serve` returns.
- Byte stream per connection: TCP → ssh stdin (stdin closed on TCP EOF, so
  dial-stdio half-closes the socket); ssh stdout → TCP (TCP write half shut
  on EOF). The child is killed and reaped when the stdout side ends, or
  after a bounded drain once the TCP side has ended.
- The bytes the daemon receives are those the browser sent, over the same
  unix socket the `-L` forward reached, so the daemon's Host and origin
  guard (`ship-daemon/src/http.rs`) behaves as before: Host `127.0.0.1:P`
  passes, a foreign `Origin` on a POST is 403.
- First connection: before the URL is printed, `open.rs` does
  `ship_net::client::get(target, "/healthz", timeout)` over its own
  dial-stdio child. Its `TransportError` already carries ssh's stderr
  (`SshUnreachable`, `Remote`, `ShipNotInstalled`), so a refusal is printed
  with ssh's own reason, and no URL is printed (OVERVIEW §3.3).
- The local port is bound by `ship` itself before ssh runs, so an occupied
  port fails at bind (f-010's guarantee holds without a probe race).
- `SshTarget::forward_args` and its test are removed (no remaining caller).

## Definition of Done

1. `ship open` over `ssh://` never runs `ssh -L`/`-N`; every ssh it runs is
   `ssh_args` (`… -- HOST ship dial-stdio [--socket S]`).
2. The listener is 127.0.0.1 only (`bind_loopback`); `--port N` that is
   occupied fails with a message naming the port, no URL, no ssh run.
3. Concurrent connections each get their own child; at most
   `MAX_CONNECTIONS` children run at once.
4. SIGINT/SIGTERM: accepting stops, every child is killed and reaped, the
   port is closed, exit 0.
5. A first connection that fails prints ssh's stderr reason, exits 1, no URL.
6. Same Host/origin guard results through the forward as before.
7. `cargo fmt`, clippy `-D warnings`, `metis verify --post --slice fix-0005`
   green. No new crate dependency (tokio features `sync`, `macros` added to
   ship-net's existing tokio).

- `cli_open.rs`, with the cli_client-style fake `ssh` (sh script that execs
  the real `ship dial-stdio`, appending each pid):
  - `ssh_serves_the_ui_through_dial_stdio_until_sigint`: URL printed;
    `/healthz` and `/` (UI index or not-built 503) served; recorded argv is
    exactly `ssh_args`'s (`… -- lab.example ship dial-stdio --socket S`);
    several concurrent requests (held open together) all answer 200; an idle
    connection holds a live child; SIGINT → exit 0, every recorded pid dead,
    port closed.
  - `ssh_keeps_the_host_and_origin_guard`: GET `/api/v1/host` with Host

    to stderr and exits 255 → exit 1, stderr contains the message, no URL,

  touches): bytes round-trip; with a limit of 1 a second connection is not
  served while the first is held and is served once it closes; shutdown
  with live connections kills and reaps their children and closes the
  port; a failing child's stderr and a missing program are reported.

## Out-of-scope touches

- `crates/ship-net/src/client.rs`: `read_bounded` made `pub(crate)` (no
  other change) so `forward.rs` reuses it rather than a third copy.
- `crates/ship-net/tests/forward.rs` (new): the `serve` tests spawn
  processes. Run as unit tests they made the existing
  `listener::tests::stale_socket_is_replaced` fail (seen once in verify): a
  fork in the same process briefly holds the fd of the unix listener that
  test has just dropped, so its connect succeeds. In their own test binary
  they cannot. `forward.rs` keeps only the non-spawning dialer test.

## Report

- `crates/ship-net/src/forward.rs` (new): `Dialer` (`Dialer::ssh` =
  `ssh` + `SshTarget::ssh_args`), `Forward { dialer, limit, drain }`,
  `serve(listener, forward, shutdown, on_error)`. Per connection one child,
  TCP→stdin (stdin closed on EOF), stdout→TCP (write half shut on EOF);
  semaphore slot taken before `accept`; on shutdown the listener is dropped,
  a watch signal kills every child and `serve` joins all tasks (children
  reaped) before returning. Child exit ≠ 0 with stderr → `on_error`.
- `crates/ship/src/open.rs`: `over_ssh` binds 127.0.0.1 via
  `ship_net::bind_loopback` (occupied `--port` fails, naming the port, before
  any ssh), probes `/healthz` with `ship_net::client::get` over a dial-stdio
  child (failure prints `TransportError`, which carries ssh's stderr), then
  prints the URL and runs `forward::serve` (`MAX_CONNECTIONS = 16`,
  drain = `DRAIN_AFTER_INPUT_EOF`) until SIGINT/SIGTERM; exit 0.
  `port_is_free`, the retry loop and the local `read_bounded` are gone.
- `crates/ship-net/src/target.rs`: `forward_args` and its test removed.
  OpenSSH `-L` is not kept as anything: one path, dial-stdio.
- `crates/ship-net/Cargo.toml`: tokio features `macros`, `sync` added (no
  new crate; Cargo.lock unchanged).
- `crates/ship/tests/cli_open.rs`: fake ssh replaced by the cli_client-style
  sh script (execs real `ship dial-stdio`, appends pids). New
  `ssh_serves_the_ui_through_dial_stdio_until_sigint` (argv exact, `/healthz`,
  `/`, 4 concurrent connections each with its own child, idle connection's
  live child killed on SIGINT, all pids dead, port closed),
  `ssh_keeps_the_host_and_origin_guard` (host 200; foreign Origin POST 403;
  Host evil.example 403), `ssh_refusal_prints_ssh_reason`;
  `ssh_refuses_an_occupied_port` now asserts no ssh ran.
- `crates/ship/tests/ssh_real.rs`: doc comment only.
- Unit tests added in `open.rs`: `probe_responses`,
  `an_occupied_port_is_refused_by_name`.
- `metis verify --post --slice fix-0005`: ALL GREEN (macOS). Real-sshd and
  Tailscale SSH runs not done here: CI `ssh` job and the supervisor.
