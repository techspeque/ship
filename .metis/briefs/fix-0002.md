# fix-0002 — A predecessor's SocketFile deletes its successor's socket when Linux reuses the inode

- **Type:** fix | **Risk:** high | **Priority:** p1
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-25
- **Plan:** .metis/plans/phase-0-plan.md §0.4

## Goal

A `SocketFile` removes the path only while it still names the socket that
`bind_unix` created, even when the filesystem hands that socket's inode
number to a successor, so §0.4's "a stale socket from a crashed daemon is
replaced safely" and "SIGTERM … removes the socket" never delete a live
successor's socket.

## Architectural context

- `crates/ship-net/src/listener.rs` — `SocketFile` records `(dev, ino)` at
  bind; `remove_inner` unlinks when `lstat(path)` matches. Once the
  predecessor's listener is closed, its socket inode is freed. A successor
  binding at the same path can get the same inode number (ext4 and tmpfs
  on Linux do this; CI linux amd64 failed `remove_leaves_a_successor_socket`
  at listener.rs:381 with `NotFound`). The predecessor's `remove()`/`Drop`
  then unlinks the successor's live socket.
- `crates/ship-daemon/src/lib.rs:108,135` holds the `SocketFile`; its API
  (`bind_unix`, `SocketFile::path`, `SocketFile::remove`, `Drop`) is unchanged.
- Approach, checked rather than assumed:
  - **ctime with nanoseconds is rejected.** Linux stamps inode times from
    the coarse clock (jiffy granularity, 1–10 ms; multigrain timestamps
    only on some filesystems and kernels), so two binds in the same tick
    get equal ctimes. That is exactly the back-to-back restart case, and the
    check could still match a different socket.
  - **Holding a dup of the socket fd is rejected.** It keeps the socket
    listening after the daemon closes its listener, so a successor would see
    `InUse` instead of a stale socket.
  - **Chosen: pin the inode (Linux).** At bind, while the bound socket
    is alive, `bind_unix` opens the path `O_PATH | O_NOFOLLOW | O_CLOEXEC`.
    That fd references the filesystem inode, not the socket, so it does not
    accept connections or keep the socket listening. But the inode cannot
    be freed while the fd is open, and so its number cannot be given to any
    other file on that device. `remove_inner` unlinks only when `lstat(path)`
    matches `fstat(pin)` and the identity recorded at bind. A match cannot be
    a different socket. The pin is dropped after the remove decision.
  - Non-Linux (macOS; `ship daemon` is Linux-only, ADR-0002) cannot `open` a
    socket and keeps the recorded `(dev, ino)` check. APFS and HFS+ do not
    reuse inode numbers.
  - The process umask is still never touched (f-003). `O_PATH` and `fstat`
    are not affected by it.
- Residual, unchanged by this slice: `lstat` → `unlink` is not atomic. A
  successor that replaces the path in between is still unlinked. POSIX has no
  conditional unlink. Closing that window needs a lock, which is out of
  scope here.

## Definition of Done

1. On Linux, `SocketFile` holds an `O_PATH | O_NOFOLLOW` fd to the socket
   it bound, opened before `bind_unix` returns while the listener is alive,
   and checked to be a socket whose identity equals the recorded `(dev, ino)`.
   A failure to open or stat the pin removes the new socket and returns
   `BindError::Io`.
2. `remove()`/`Drop` unlink the path only when `lstat(path)` equals both the
   recorded `(dev, ino)` and (Linux) `fstat(pin)`. Otherwise the path is left
   alone. `NotFound` is `Ok(())`, as before.
3. The process umask is never changed. `concurrent_file_creation_is_unaffected`
   stays green.
4. `remove_leaves_a_successor_socket` passes on Linux 50 consecutive runs.
5. A test forces the same-inode case instead of waiting for the filesystem
   to reuse a number, and the successor survives.
6. `metis verify --post --slice fix-0002` is green. No new dependency.

## Test plan

- `remove_leaves_a_successor_socket` (existing, unchanged): predecessor's
  listener dropped, successor bound, predecessor `remove()` leaves the
  successor. Looped 50× on Linux.
- `remove_leaves_a_successor_with_the_same_inode_number` (new): forces the
  collision the old check fell for by overwriting the predecessor's recorded
  `(dev, ino)` with the successor's. The path now matches the predecessor's
  recorded identity. On Linux, `remove()` and `Drop` must leave the
  successor live and connectable, because only the pin tells them apart.
  The test is `cfg(target_os = "linux")`. Elsewhere the recorded numbers
  are the whole identity by design.
- `pin_does_not_keep_the_socket_listening` (new, Linux): after the listener
  is dropped while the `SocketFile` is alive, a connect is refused, so a
  successor still sees the socket as stale.
- Existing listener tests unchanged and green: mode 0660, stale replaced,
  live refused, non-socket untouched, own socket removed by `remove` and by
  `Drop`, umask unaffected.

## Report

- `crates/ship-net/src/listener.rs`:
  - `SocketFile` gains `pin: fs::File` (Linux only), opened
    `O_PATH | O_NOFOLLOW` by the new `identify()` while the bound socket is
    alive. `identify()` checks that the pin is a socket with the same
    `(dev, ino)` as `lstat(path)`. If not, or if the open or the stat fails,
    `bind_unix` removes the new socket and returns `BindError::Io`.
  - `remove_inner` → `is_ours()`: the path must match the recorded
    `(dev, ino)` and, on Linux, `fstat(pin)`. `NotFound` from either stat or
